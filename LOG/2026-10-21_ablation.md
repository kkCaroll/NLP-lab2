# 无测试消融执行记录

## 目的

检验移除测试执行后，负面反馈与修复成功、修改规模的关系是否改变。主实验中 Bash 仅允许运行 pytest，消融中所有 Bash 调用被拒绝，第一轮提示词明确说明当前环境不允许运行测试。

## 设置

| 项目 | 内容 |
|---|---|
| run_id | 2026-10-21_ablation |
| 模型 | MiniMax-M3.1-Flash 与 MiMo-V2.6-Flash |
| 任务 | T05、T06、T13、T14、T18、T19、T20、T24 |
| 条件 | 五条件，任务内随机顺序 |
| 第一轮工具调用 | 10 |
| 第二轮工具调用 | 15 |
| 编辑上限 | 8 |
| 超时 | 300 秒 |
| 配置 | harness/configs/ablation/opencode.json |
| 配置哈希 | 56b4136398460cdfe99d56815228fdb112b33cdcd659fba688da5af15d5c6a22 |
| 开始时间 | 2026-10-21 22:17:59 |

执行命令如下。

```bash
python harness/run_batch.py --run-id 2026-10-21_ablation \
  --models opencode/minimax-m3.1-flash-free,opencode/mimo-v2.6-flash-free \
  --tasks T05_email_regex T06_version_scan T13_paginate T14_shipping_fee \
  T18_parse_bool T19_to_decimal T20_multi_key_sort T24_join_path \
  --no-tests
python harness/audit_run.py --run-id 2026-10-21_ablation --check-initial-logs
python harness/aggregate.py --run-id 2026-10-21_ablation \
  --output RECORD/analysis/ablation
python harness/count_tool_attempts.py --run-id 2026-10-21_ablation
python harness/analyze.py \
  --reliability RECORD/analysis/reliability/episode_level.csv \
  --ablation RECORD/analysis/ablation/episode_level.csv
```

## 完整性

审计输出为 records 16、branches 50、ok true。无缺失 summary、无缺失分支、无超时、无分支继承不一致、无提示词公共前缀差异、无初始日志不一致、无测试篡改。

条件顺序随机化生效。每题 `task_summary.json` 与 `run_config.json` 均记录 `condition_order` 与派生种子。第一轮提示词不允许运行测试，第二轮提示词仍包含第一轮失败日志。

无测试执行由事件流核验。六十六个 episode 中二十五个出现 Bash 尝试，共二十六次。二十六次均返回工具不可用，成功完成零次，权限拒绝零次，二十六次同时计为无效工具调用。测试篡改计数为零。

## 结果

MiniMax 第一轮八题全部失败，四十个分支 episode。MiMo 第一轮六题通过，仅 T13 与 T14 进入分支，十个分支 episode。

MiniMax 全样本通过数为 29/40，消融为 33/40，通过率由 0.725 升至 0.825。分条件通过数为 pure_continue 7 升至 8，neutral 5 升至 7，method_guidance 6 升至 8，negative 4 保持 4，negative_guidance 7 降至 6。

MiMo 全样本通过数为 38/40，消融为 40/40。只有 neutral 与 negative 各由 7 升至 8，其余条件不变。MiMo 的第一轮通过数由两题升至六题。

MiniMax 的 negative 仍为五条件最低。negative 与 negative_guidance 的预算耗尽分别为 7/8 与 8/8，失败以未编辑为主。negative 四题失败中三题未编辑，negative_guidance 两题失败均未编辑。

## 发现

1. 随机顺序与移除测试执行后，MiniMax 的 negative 仍低于 pure_continue 与 method_guidance。
2. negative_guidance 未恢复到 pure_continue 水平，消融中反而比主运行少通过一题。
3. 无测试环境整体通过率更高，但增益集中在 pure_continue、neutral 与 method_guidance，negative 没有改善。
4. MiMo 第一轮通过数明显上升，提示测试调用可能消耗有限预算，也可能反映运行间波动。该结果只基于一次运行。
5. negative 的 EditSize 较低来自未编辑失败，不能解释为修改更谨慎。

## 数据修正

`run_batch.py` 在无测试模式下原先按命令行默认值把主配置路径写入批清单，虽然实际传给单题运行器的是消融配置。已在批处理脚本中先解析有效配置再计算路径与哈希，并按逐题 `run_config.json` 更正本次批清单的 `config` 与 `config_sha256` 字段。该修正只涉及元数据，不改变任何 episode、评分或结果。
