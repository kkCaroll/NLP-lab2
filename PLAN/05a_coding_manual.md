# 质性编码手册

> 所属计划：[05_deepening.md](05_deepening.md)
> 适用材料：三十一条分支 episode
> 状态：用户已复核三条判断规则，首轮三十一条编码已完成，等待间隔重编码

## 1. 目的

编码用于回答两个问题。

1. 负面反馈失败时，智能体停在何处，是未编辑、反复搜索、预算耗尽，还是改错。
2. 方法指引是否改变了定位行为，例如先读日志、查找调用方、限制修改范围。

编码只描述可观察行为，不推断模型意图，不把语气当作证据。

## 2. 分析单位

一个分支 episode 为一条编码记录。每条记录对应第一轮失败后的一个第二轮分支。第一轮通过的题不进入编码。

证据来源限定为以下五类。

| 来源 | 用途 |
|---|---|
| `events.jsonl` | 工具调用顺序、读取与搜索行为、编辑次数 |
| `diff_cumulative.patch` | 第二轮结束时的累计修改 |
| `diff_delta.patch` | 第二轮相对第一轮的修改 |
| `round1_diff.patch` | 第一轮修改，用于判断是否回退 |
| `final_text.txt` | 最后一条助手文本，用于判断是否宣称完成 |

`summary_redacted.json` 只提供结果、编辑行数、工具调用数、预算状态与允许文件，不提供模型与条件。

## 3. 盲化

1. 材料按匿名编号 S01 至 S31 排列，编码表中不出现模型名、条件名与任务名。
2. 不向编码者提供 `prompt.txt`，避免条件措辞直接暴露分组。
3. `blinding_manifest.csv` 保存编号与原始 episode 的对应关系，编码期间不打开。
4. 编码完成后才允许按编号回查条件，用于分组汇总。

无法完全盲化的部分在报告中说明。编码者可能从任务结构与失败模式推断题目，但不应看到反馈条件。

## 4. 编码值

每个编码取以下四值之一。

| 值 | 含义 |
|---|---|
| 是 | 有直接证据表明该行为发生 |
| 否 | 有直接证据表明该行为未发生 |
| 不适用 | 该行为在本次 episode 中没有定义，例如未编辑时的修改范围 |
| 不确定 | 材料不足或证据冲突，必须在备注中写明原因 |

`不确定` 不应作为默认值。能在事件流或 diff 中确认的判断，不得填不确定。

## 5. 编码定义

### 5.1 no_edit

由 `summary_redacted.json` 的 `edits` 字段直接得到。`edits` 为零记是，否则记否。该字段不参与人工判断，用于解释后续不适用值。

### 5.2 reads_log_first

含义为第一次编辑之前是否读取错误日志或测试输出。

- 是。首次编辑前存在读取 `pytest.txt`、初始测试日志、错误输出或测试报告的工具调用。
- 否。首次编辑前没有任何此类读取。
- 不适用。episode 未发生编辑。

只读取源码、README 或测试文件不算读取错误日志。读取测试文件本身也不等于读取测试输出。

### 5.3 locates_callers

含义为 episode 内是否主动查找目标函数的调用方或相关模块。

- 是。出现 grep、glob 或读取其他模块，且输入或路径明确指向调用方、导入方或相关模块。
- 否。只读取目标文件与测试文件，未查找调用方。
- 不适用。该编码在未编辑 episode 中仍有定义，不使用不适用。

仅搜索目标函数名以定位定义，不算查找调用方。必须表现出跨文件的关系追踪。

### 5.4 only_target_lines

含义为累计 diff 是否只触碰目标函数的必要行。

- 是。修改集中在目标函数，未改动无关函数、格式、注释或导入。
- 否。出现无关函数修改、整文件格式化、无关导入调整或明显超出缺陷范围的改动。
- 不适用。episode 未发生编辑。

判断以 diff 为准，不以修改行数多少为准。目标函数内的小范围重写仍可记是。

### 5.5 rewrites_function

含义为是否整体重写目标函数，而非局部修改。

- 是。目标函数主体大部分被替换，或删除后重新实现。
- 否。在原有结构上做局部增删改。
- 不适用。episode 未发生编辑。

以 diff 的删除比例与结构变化判断。仅改动三行但替换了核心分支，仍可能记是，需在备注说明。

### 5.6 unrelated_file

含义为是否修改目标文件之外的文件。

- 是。累计 diff 出现允许文件之外的文件。
- 否。所有修改都在允许文件内。
- 不适用。episode 未发生编辑。

允许文件由 `summary_redacted.json` 的 `allowed_files` 给出。测试文件被修改时另记测试篡改，不并入本编码。

### 5.7 defensive_branch

含义为是否增加测试未要求的防御性分支或异常吞没。

- 是。新增 try/except、空值兜底、宽泛类型转换、静默返回等，且测试未要求该行为。
- 否。修改直接针对失败断言，没有额外防御逻辑。
- 不适用。episode 未发生编辑。

为满足明确的边界测试而增加判断，不算防御性分支。判断标准是测试是否要求该行为。

### 5.8 reverted_previous

含义为是否回退或重写第一轮方案。

- 是。第二轮删除或替换了第一轮引入的主要修改。
- 否。第二轮在第一轮基础上增量修改，或第一轮没有修改。
- 不适用。episode 未发生编辑。

以 `round1_diff.patch` 与 `diff_cumulative.patch` 对照。仅修正第一轮的一行错误不算回退，必须改变第一轮的主要方案。

### 5.9 claims_done_unverified

含义为是否在缺少通过证据时宣称完成。

- 是。最后文本声称已修复或测试通过，但 `summary_redacted.json` 显示未全部通过，或本轮没有成功运行测试。
- 否。最后文本承认仍未通过、说明不确定，或明确列出未验证部分。
- 不适用。没有助手文本。

最后文本中的礼貌用语不影响判断。只看是否作出可验证的完成声明。

## 6. 编码流程

1. 打开 `summary_redacted.json`，记录结果、编辑次数、工具调用数与预算状态。
2. 按时间顺序阅读 `events.jsonl`，在纸上或备注中记下工具调用序号。
3. 找到首次编辑的调用序号，回看此前的读取与搜索行为。
4. 阅读 `diff_cumulative.patch`、`diff_delta.patch` 与 `round1_diff.patch`。
5. 阅读 `final_text.txt`。
6. 填写编码表，每个判断写一句证据，附工具调用序号或 diff 行号。
7. 全部完成后才打开 `blinding_manifest.csv` 做分组汇总。

## 7. 重编码与一致性

1. 完成三十一条后至少间隔二十四小时，随机抽取十条重编码。
2. 重编码时不查看第一次编码表。
3. 对每个编码计算原始一致率与 Cohen kappa。kappa 受边际分布影响时同时报告一致率与不一致条目。
4. 若条件允许，邀请一位同学独立编码同样的十条，报告编码者间一致率。没有第二编码者时在报告中明确说明。

## 8. 常见错误

1. 把未编辑失败记为否，而不是不适用，导致修改范围类编码被低估。
2. 把读取测试文件当作读取测试输出。
3. 把搜索目标函数定义当作查找调用方。
4. 用修改行数判断是否过度修改，而不看修改位置与测试要求。
5. 看到负面措辞后推断模型意图，而不是依据工具调用与 diff。
6. 把测试篡改与无关文件修改混为一谈。

## 9. 输出格式

`coding_sheet.csv` 每行一条 episode，列如下。

| 列 | 内容 |
|---|---|
| sample_id | S01 至 S31 |
| no_edit | 是 否 |
| reads_log_first | 是 否 不适用 不确定 |
| locates_callers | 是 否 不确定 |
| only_target_lines | 是 否 不适用 不确定 |
| rewrites_function | 是 否 不适用 不确定 |
| unrelated_file | 是 否 不适用 不确定 |
| defensive_branch | 是 否 不适用 不确定 |
| reverted_previous | 是 否 不适用 不确定 |
| claims_done_unverified | 是 否 不适用 不确定 |
| evidence | 每个判断对应的工具调用序号或 diff 行号 |
| notes | 边界情况说明 |

编码完成后另写 `coding_memo.md`，记录编码过程中修改过的定义、难以判断的条目与对结果的初步观察。初步观察不得写成因果结论。
